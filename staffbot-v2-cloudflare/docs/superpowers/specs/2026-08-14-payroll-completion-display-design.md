# 工资完成态移动端显示设计

日期：2026-08-14
环境：先发布到 staging，live 不在本次范围内

## 目标

员工在 Telegram 确认收到工资后，管理员应能在移动管理端直接看懂这笔工资已经完成，并能追溯工资周期、付款版本、工资 ID、确认账号、确认时间和付款回执。

## 已确认的问题

- 工资列表显示 `confirmed · 未领取`，完成状态与领取状态相互矛盾。
- 工资档案直接显示 `confirmed`、`employee_confirmed` 和员工反馈 `confirmed`。
- 确认时间直接截取 UTC 字符串，没有按店铺时区显示。
- 处理时间线直接暴露内部 action 名称。
- 付款回执已能正常展示和留存，不需要修改。

## 方案比较

### 方案 A：仅修改移动端渲染（采用）

复用现有 API 中的状态、确认时间、员工账号、工资 ID、付款版本和店铺时区，只增加前端中文映射与完成态摘要。优点是改动小、无需迁移、不会改变工资业务状态；缺点是其他客户端若存在，需要各自实现显示映射。

### 方案 B：API 直接返回中文文案

后端为每种状态和审计动作返回显示文案。可以统一多个客户端，但把界面语言耦合进 API，当前只有中文管理端，不值得扩大接口。

### 方案 C：完整国际化系统

建立多语言键值与时区展示组件。扩展性最好，但明显超出本次修复范围。

## 界面设计

### 工资列表

- `confirmed` 显示为“员工已确认”。
- 已完成工资不再显示“未领取”，改为“已完成”。
- 其他仍需管理员处理的工资保留现有处理人或领取状态。

### 工资档案

- 顶部 `confirmed` 显示为“工资已完成”。
- 已完成工资隐藏“当前未领取”。
- 在固定工资事实中增加：工资 ID、确认账号、确认时间。
- 确认时间及工资相关时间统一按员工所在店铺的时区格式化，并标注“店铺时区”。

### 付款版本

- `draft` 显示“付款草稿”。
- `submitted` 显示“等待员工确认”。
- `employee_confirmed` 显示“员工已确认”。
- `employee_disputed` 显示“员工反馈付款问题”。
- 员工反馈 `confirmed` 显示“已确认收到工资”；`disputed` 显示“付款有问题”。

### 处理时间线

本次工资相关内部 action 映射为可读中文；未知 action 仍显示原值，避免丢失审计信息。至少覆盖领取、创建付款版本、保存付款拆分、上传回执、提交付款、通知成功或失败、员工确认。

## 数据与安全边界

- 不修改数据库结构、工资状态机、金额计算、回执存储或 Telegram 流程。
- 不删除任何历史审计记录。
- 不改变仍在处理中的工资领取逻辑。
- 所有动态内容继续经过现有 HTML 转义。

## 验收标准

1. 已确认工资列表显示“员工已确认 · 已完成”，不出现英文状态或“未领取”。
2. 工资档案显示“工资已完成”、工资 ID、确认账号和店铺时区确认时间。
3. 付款版本和员工反馈均显示中文。
4. 两张付款回执继续正常显示。
5. 工资相关时间线 action 显示中文。
6. 未完成工资的领取、付款和通知操作行为不变。
7. 自动化测试、语法检查和 staging 手机浏览器实测全部通过。
