# 逐员工缺勤检查开关设计

## 目标

允许管理员按“店铺 + 员工”决定该员工是否需要每天检查缺勤，减少不需要固定出勤员工产生的无效审批，同时保持现有员工的默认行为不变。

## 已确认规则

- 每个店铺员工拥有独立的“检查每日缺勤”开关。
- 同一员工加入多个店铺时，各店铺可分别设置。
- 现有员工和新员工默认开启。
- 开启时，员工参与每日缺勤计算、缺勤审批和缺勤罚款流程。
- 关闭时，员工不计算缺席天数，不生成新的缺勤审批或缺勤罚款；其实际工作、迟到、请假和已有罚款统计仍正常显示。
- 关闭时，系统取消该员工在当前店铺所有尚未审批的缺勤请求，并停止对应的待发送通知。
- 已批准、已驳回或已取消的历史缺勤记录保持不变；已经批准产生的罚款不会因关闭开关而自动修改。
- 重新开启只影响重新开启后的营业日，不补算关闭期间的缺勤。

## 方案比较

### 采用：在店铺员工关系上增加开关

在 `store_members` 增加布尔字段。现有员工管理页面已经支持逐员工编辑，因此只需在原表单和列表中增加一个开关/状态列。缺勤扫描和考勤统计直接读取该字段。

这是改动最小且语义最准确的方案，因为规则属于员工在某个店铺的出勤要求，而不是员工的全局属性。

### 不采用：店铺级免检名单

把员工 ID 列表存入店铺设置虽然能少建一个字段，但编辑、校验和查询都更复杂，也不便于在员工列表中查看状态。

### 不采用：新增排班系统

完整排班能表达按星期或按日期出勤，但当前需求只有“是否每日检查”两种状态。新增排班表和排班界面会显著扩大范围。

## 数据设计

在 `store_members` 新增：

- `absence_check_enabled INTEGER NOT NULL DEFAULT 1`

`1` 表示参与每日缺勤检查，`0` 表示免检。数据库默认值保证迁移后的现有员工继续参与检查。

更新员工接口时：

- 明确提交开关值时，保存为 `1` 或 `0`。
- 旧客户端未提交该字段时，新增员工默认 `1`，编辑现有员工则保留当前值，避免兼容性回归。

## 管理页面

复用现有“员工管理”页面，不新增页面或弹窗：

- 员工编辑表单增加“检查每日缺勤”选择框，选项为“开启”和“关闭”。
- 员工列表增加“缺勤检查”列，直接显示开启/关闭。
- 点击编辑员工时回填当前值。
- 清空表单或新建员工时默认开启。

页面继续使用现有深色主题、输入框、表格和多语言文案，不引入新 UI 组件或依赖。

## 业务流程

### 定时扫描

现有缺勤候选员工查询增加 `absence_check_enabled = 1` 条件。其他规则保持不变：员工必须启用、角色为员工、当天没有签到且没有已批准请假。

### 关闭开关

保存员工设置并从开启变为关闭时，在同一个 D1 批处理中：

1. 更新员工开关。
2. 将该店铺、该员工所有 `pending` 缺勤请求改为 `cancelled`，取消原因为“管理员关闭缺勤检查”。
3. 将这些请求尚未发送或正在重试的通知标记为取消，防止 Cron 后续发送。

若批处理失败，整个保存操作失败，不留下“开关已关闭但审批仍待处理”的中间状态。

### 重新开启

员工记录增加一个本轮启用时间，用来建立重新启用边界：

- `absence_check_enabled_at TEXT`

迁移时现有员工使用其 `joined_at` 作为当前启用边界，以保持现有历史统计。由于店铺级功能本身已有启用日期，实际罚款扫描起点取店铺启用日期、员工启用日期和店铺扫描进度中的有效边界。

关闭时清空该时间；重新开启时记录当前时间。缺勤扫描只处理不早于员工本轮启用日期的营业日，因此不会补算免检期间。

为了让新员工和旧客户端写入行为一致，新员工默认开启时记录创建时间；现有员工在迁移后由迁移语句统一写入各自的 `joined_at`。

## 考勤统计

员工仍出现在多员工考勤列表中，避免丢失其实际工作信息：

- 实际工作天数、迟到天数、已批准请假和罚款总额继续正常统计。
- 开关关闭时，缺席天数固定为 `0`。
- 开关开启时，缺席计算的开始日期不得早于员工本轮启用日期。
- 顶部汇总卡继续按员工列表汇总，因此免检员工不会增加缺席总数。

这项规则只改变缺席口径，不改变签到、迟到、请假或财务历史。

## 并发与审计

- 员工设置更新继续写入现有管理员审计日志，并记录开关变化。
- 关闭开关与取消待审批记录使用同一批处理。
- 已被其他管理员抢先批准的记录不再满足 `pending` 条件，因此不会被取消或修改罚款。
- 通知发送前现有逻辑仍会复查请求状态；即使通知任务与关闭操作并发，也不会发送已取消的审批。

## 测试与验收标准

1. 数据迁移后所有现有员工默认开启缺勤检查。
2. 新增员工默认开启；旧客户端省略字段时不会意外关闭现有员工。
3. 管理员可在员工管理页面查看、编辑并回填开关。
4. 关闭员工不会被 Cron 选为缺勤候选人。
5. 关闭时，该员工当前店铺的待审批缺勤和待发送通知被取消。
6. 关闭不会修改已批准的罚款或其他历史记录。
7. 免检员工仍显示工作、迟到、请假和罚款统计，但缺席为 `0`。
8. 重新开启后只从重新开启当天开始检查，不补算关闭期间。
9. 同一员工在不同店铺的开关互不影响。
10. 原有签到、签退、请假、收入、工资和其他员工的缺勤检查测试继续通过。
