# StaffBot Staging 管理员操作手册

版本：2026-08-14  
适用环境：StaffBot staging 测试环境  
适用设备：iPhone（Safari / 主屏幕网页 App）

## 1. 这份手册适用于什么

本手册供管理员在 **staging 测试环境**中使用 StaffBot。

管理员主要使用两个入口：

- 手机管理端：处理待办、审批和工资付款。
- Telegram 测试机器人：接收登录验证码、业务通知和异常提醒。

员工继续在 Telegram 中提交收入、请假、预支工资、考勤、收款信息和工资确认。

> 重要：staging 是测试环境。不要使用真实付款、真实银行卡资料、真实 USDT 资产或无法撤销的业务数据。staging 操作不会自动进入 live 环境。

## 2. Staging 地址和机器人

- 手机管理端：<https://staffbot-v2-staging.staffbot-v2.workers.dev/manage/>
- 电脑管理后台：<https://staffbot-v2-staging.staffbot-v2.workers.dev/admin>
- Telegram 测试机器人：`@staffbot_v2_staging_bot`

请先确认自己打开的是带有 `staging` 的地址和测试机器人，不要把测试步骤发给 live 机器人。

## 3. 使用前准备

每位管理员都应使用自己的 Telegram 账号，不要多人共用一个管理员账号。

请让系统负责人确认：

1. 你的 Telegram 数字 ID 已加入 staging 管理员权限。
2. 你的 Telegram 数字 ID 已加入 staging 消息白名单。
3. 你已被分配到需要管理的店铺，角色为 `admin` 或 `owner`。
4. 你知道自己的 Telegram 数字 ID。

不要把登录验证码、Bot Token、Webhook Secret 或管理员会话转发给任何人。

## 4. 设置 Telegram 测试机器人

staging 机器人已经由系统部署完成。管理员不需要使用 BotFather，也不需要设置 Token。

你只需要启用机器人：

1. 在 Telegram 搜索 `@staffbot_v2_staging_bot`。
2. 确认用户名完全一致。
3. 点击“开始”或发送 `/start`。
4. 收到机器人回复后，保持该聊天窗口可用。
5. 不要屏蔽或删除机器人，否则可能收不到登录验证码和业务通知。

如果发送 `/start` 没有回复：

- 检查是否打开了正确的 staging 机器人。
- 检查网络。
- 联系系统负责人检查 Telegram 白名单和 webhook。

## 5. 在 iPhone 安装管理 App

StaffBot 管理端是 PWA 网页 App，不需要 App Store 或 TestFlight。

1. 在 iPhone 上打开 **Safari**。
2. 访问：<https://staffbot-v2-staging.staffbot-v2.workers.dev/manage/>
3. 点击 Safari 的“共享”按钮。
4. 向下滚动，选择“添加到主屏幕”。
5. 如果出现“作为网页 App 打开”，请保持开启。
6. 点击“添加”。
7. 回到主屏幕，找到 `StaffBot` 图标。
8. 从主屏幕图标启动管理端。

如果看不到“添加到主屏幕”，请在共享菜单底部选择“编辑操作”，把该操作加入菜单。

## 6. 登录管理端

1. 打开主屏幕上的 StaffBot。
2. 在“Telegram 管理员 ID”中输入自己的 Telegram 数字 ID。
3. 点击“发送验证码”。
4. 打开 `@staffbot_v2_staging_bot`，读取验证码。
5. 回到 StaffBot，输入验证码。
6. 点击“登录”。
7. 登录后，页面顶部会显示当前管理员 ID。

注意：

- 验证码只能短时间使用。
- 验证码成功使用一次后不能再次使用。
- 不要连续大量点击“发送验证码”。
- 每位管理员必须使用自己的账号，以便审计记录能显示实际操作人。

## 7. 手机管理端界面

底部有四个入口：

### 7.1 待办

显示需要处理的收入、请假、缺勤罚款、预支工资等任务。

可使用：

- 店铺筛选。
- 任务类型筛选。
- “查看详情”进入任务。

优先任务会排在普通任务前面。

### 7.2 审批

集中处理可以批准或驳回的业务申请。

### 7.3 工资

查看全部工资档案、待付款工资、争议工资和已完成工资。

### 7.4 更多

查看当前登录账号或退出登录。

> Dashboard、员工维护、店铺设置、宽表查询和 CSV 导出目前仍在电脑 `/admin` 后台，不在手机 App 的“更多”中。

## 8. 通用审批操作

### 8.1 打开任务

1. 进入“待办”或“审批”。
2. 选择店铺和任务类型。
3. 点击任务的“查看详情”。
4. 核对员工、店铺、金额、业务日期、提交时间、附件和历史。

### 8.2 领取任务

普通审批任务需要先领取，领取后才能修改状态。

- 未被领取：可以点击领取。
- 已由自己领取：可以继续处理。
- 已由其他管理员领取：页面只读，并显示处理人。
- 确需处理时，可按页面提示进行负责人接管并填写原因。

不要在没有核对原始资料时强制接管其他管理员的任务。

### 8.3 批准

1. 核对申请内容。
2. 点击“批准”。
3. 在确认区域再次确认。
4. 等待页面显示最新结果。

连续点击不会产生两次审批，但仍应等待页面完成刷新。

### 8.4 驳回

1. 点击“驳回”。
2. 填写清楚、可理解的驳回原因。
3. 确认提交。
4. 员工会在 Telegram 收到驳回结果和原因。

## 9. 各类审批说明

### 9.1 收入

核对：

- 员工和店铺。
- 原始收入。
- 提成比例。
- 最终提成收入。
- 提交时间。

批准后，正式工资流水增加一条收入记录。驳回后不进入工资计算。

### 9.2 请假

核对请假日期、店铺规则、当日人数限制和员工本月请假情况。

批准请假后，该日期不应因为正常缺勤扫描而自动形成实际缺勤罚款。请假申请和正式工资罚款是两类不同记录。

### 9.3 缺勤罚款

核对考勤、已批准请假、业务日期和罚款金额。

只有批准后写入正式工资流水的负数记录，才会影响工资。待审核或已驳回的罚款申请不等于实际扣款。

### 9.4 预支工资

核对员工当前可用工资、申请金额和是否已有待处理申请。

批准后，预支金额作为负数工资流水进入当前周期；驳回后不扣减工资。

## 10. 工资付款完整流程

### 10.1 打开工资档案

1. 点击底部“工资”。
2. 选择店铺。
3. 找到目标员工。
4. 核对金额、状态和截止时间。
5. 点击“查看工资档案”。

工资档案中的固定事实包括：

- 员工和店铺。
- 工资总额。
- 工资周期。
- 工资 ID。
- 银行卡或 USDT 收款摘要。
- USDT 二维码（员工已提交时）。
- 全部付款版本和历史回执。

工资金额是截止时间生成的固定快照。管理员不能在付款页面重新计算或修改工资总额。

### 10.2 领取并开始付款

1. 点击“领取并开始付款”。
2. 系统创建或恢复一个付款草稿版本。
3. 页面进入“本次付款”。

当前项目按单一工资付款管理员场景处理，不应因为普通等待时间阻止已领取管理员完成付款。如页面显示状态冲突，请先刷新工资档案，不要重复创建工资。

### 10.3 拆分付款金额

员工允许的方式可能包括：

- 银行卡。
- USDT。
- 现金。

填写规则：

1. 每项金额必须大于等于 0。
2. 所有付款方式之和必须精确等于工资总额。
3. 金额为 0 的方式不需要上传回执。
4. 金额大于 0 的每种方式至少需要一张回执。

例如工资总额为 `₫8,000`：

- 银行卡：`₫5,000`
- USDT：`₫3,000`
- 现金：`₫0`

总和必须为 `₫8,000`。

### 10.4 上传付款回执

每种非零付款方式都有两个入口：

- “拍照”：直接打开 iPhone 相机。
- “从相册选择”：可选择已有图片，也可一次选择多张。

操作步骤：

1. 确认所选上传区与付款方式一致。
2. 拍照或选择图片。
3. 等待每张图片显示上传成功。
4. 点击图片可以核对内容。
5. 草稿回执错误时，可点击“删除回执”并重新上传。

已提交付款版本中的回执属于留存证据，不能删除或覆盖。修正付款必须建立新版本。

### 10.5 提交付款并通知员工

按钮只有在以下条件全部满足时才可用：

- 拆分总额等于工资总额。
- 每种非零付款方式至少有一张成功回执。
- 当前网络正常。
- 页面状态没有过期或冲突。

点击“提交付款并通知员工”后：

1. 本次付款版本被固定。
2. 回执成为不可修改的历史证据。
3. 员工在 Telegram 收到工资付款信息。
4. 系统等待员工选择“确认已收到”或“付款有问题”。

提交后不要因为页面刷新稍慢而重复操作。先等待页面重新加载工资档案。

### 10.6 员工确认收到

员工确认后，工资档案会显示：

- `员工已确认 · 已完成`。
- 确认账号。
- 工资周期。
- 确认时间（店铺时区）。
- 工资 ID。
- 付款版本和全部回执。
- 中文处理时间线。

### 10.7 员工报告付款问题

如果员工点击“付款有问题”：

1. 原付款版本和回执永久保留。
2. 工资进入争议状态。
3. 管理员收到通知。
4. 管理员重新打开工资档案。
5. 系统创建新的付款版本。
6. 管理员重新填写拆分、上传新回执并提交。

不要修改或删除版本 1 来代替版本 2。

### 10.8 Telegram 通知失败

如果付款已经提交，但 Telegram 通知失败：

- 付款记录不会回滚。
- 不要重新创建付款或重复上传回执。
- 在工资档案中点击“重试 Telegram 通知”。
- 重试后核对处理时间线是否显示通知成功。

## 11. 查看已完成工资和证据

进入“工资”并打开已完成档案，可以追溯：

- 哪位员工收到工资。
- 哪个店铺。
- 哪个工资周期。
- 工资总额。
- 银行卡、USDT、现金拆分。
- 每张付款回执。
- 哪位管理员提交。
- 员工确认账号和时间。
- 历史付款版本。
- 通知失败和重试记录。

## 12. 离线和网络恢复

手机断网后，页面会显示：`当前离线，只能查看已加载内容`。

离线时：

- 不要尝试批准或驳回。
- 不要上传付款回执。
- 不要提交工资付款。
- 已加载页面仅供查看。

恢复网络后，系统会重新读取会话、店铺和最新任务状态。在刷新完成前，财务操作保持只读。

如果恢复网络后仍提示“当前页面保持只读”：

1. 返回任务或工资列表。
2. 下拉或重新打开页面。
3. 必要时关闭 App 后重新打开。
4. 仍失败时记录截图、时间、管理员 ID 和业务 ID，联系系统负责人。

## 13. 版本更新

staging 发布新版本后：

1. 关闭 StaffBot App。
2. 从后台任务列表中彻底移除。
3. 重新打开。
4. 检查修复是否生效。

不要只依赖旧页面长时间保持打开。若仍看到旧版本，可删除主屏幕图标并重新从 Safari 安装。

## 14. 电脑管理后台

电脑访问：<https://staffbot-v2-staging.staffbot-v2.workers.dev/admin>

电脑后台适合：

- Dashboard 和员工月度比较。
- 店铺设置。
- 员工维护和工资第一工作日。
- 收入、工资、预支、考勤和缺勤记录查询。
- CSV 导出。
- 日志和异常排查。

手机 PWA 与电脑后台共用同一份 staging 数据，不是两套账本。

## 15. Staging 测试安全规则

1. 只使用 staging URL 和 staging 机器人。
2. 不使用真实银行账号、真实 USDT 钱包或真实付款。
3. 所有测试金额和截图应清楚标记为测试。
4. 不把验证码和登录会话分享给其他人。
5. 测试失败时先保留证据，不要连续重复点击。
6. 每个问题记录：时间、管理员 ID、员工、店铺、业务 ID、截图和操作步骤。
7. 未明确批准前，不执行 live 部署、live 数据库迁移或 live Telegram 设置。

## 16. 常见问题

### 收不到登录验证码

- 确认已向 `@staffbot_v2_staging_bot` 发送 `/start`。
- 确认 Telegram ID 正确。
- 确认账号有管理员权限并在 staging 白名单中。
- 不要使用 live 机器人的验证码。

### 看不到某个店铺

当前管理员没有该店铺权限，或店铺已停用。联系系统负责人检查店铺成员角色。

### 无法点击批准或付款

可能原因：离线、页面正在刷新、任务由其他管理员处理、申请已经完成或业务状态已变化。返回列表并重新打开，不要重复提交。

### 回执上传失败

- 检查图片格式和网络。
- 确认从正确的银行卡、USDT 或现金上传区选择图片。
- 只重试失败的图片。

### 员工说没有收到工资确认消息

打开工资档案查看处理时间线。如果显示通知失败，点击“重试 Telegram 通知”；不要再次付款。

## 17. 每次工资付款后的检查清单

- [ ] 员工和店铺正确。
- [ ] 工资周期正确。
- [ ] 工资总额正确。
- [ ] 付款拆分合计正确。
- [ ] 每种非零方式至少有一张回执。
- [ ] 提交后出现对应付款版本。
- [ ] 员工收到 Telegram 确认消息。
- [ ] 员工确认后显示“员工已确认 · 已完成”。
- [ ] 确认账号、确认时间、工资 ID 完整。
- [ ] 银行卡和 USDT 回执可以在后台查看。
